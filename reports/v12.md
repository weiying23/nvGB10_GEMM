# v12 — 配置族 + 形状分派（小形状 +55~126%）✅ 采纳

- **日期**：2026-11-09
- **文件**：`gemm_v12.cu`（双配置模板 + 运行时分派）；`bench/gemm_cfg.cu`（参数化扫描底座）
- **前一版本**：v11（88.9 @4096³）

> **接力链**：v11 的全维度盘点指示 = 单配置打天下是中小形状的最大缺口（512³ 仅 11.8 = cuBLAS 38.06 的 31%，4×2=8 个 block 填 48 SM）→ 本版动作 = tile 配置参数化（模板化）+ 六配置扫描 + 运行时分派（block 数 < 48 → 小 tile 128×64）→ 实测 = 512³ **+123%**、768³ +55%、256³ +126%，大形状零回归（同 kernel）。

## Step 1 — 依据

全维度盘点（v11 后）：SM 填充病是中小形状最大单项缺口。512³ 用 128×256 只有 8 个 block（48 SM 里 40 个闲置）；引擎地图显示 cuBLAS 用 nvjet 64×104 小 tile + 128 线程打 512³。

## Step 2 — 方案（吸取 v4 教训：先列全维度）

**扫描维度**（v4 的教训是 WM 没被参数化导致搜索空间不完整；本轮先推导约束再列维度）：

- 结构约束：`WN = 64` 恒定（warp_n ↔ 64 列 B chunk 一一对应），`WM = BM×chunks/8`；
- 可扫维度：BM × BN ∈ {128×256, 128×128, 256×128, 64×128, 128×64, 64×256}（256×256 超 smem 99KB 排除）；
- 分派维度：按大 tile 的 block 数是否填满 48 SM 决定切换。

**扫描结果**（`bench/gemm_cfg.cu`，精度全 PASS）：

| 配置 | 512³ | 1024³ | 2048³ | 4096³ |
|---|---|---|---|---|
| 128×256（v11） | 11.80 | 57.89 | **77.05** | **82.81** |
| 128×128 | 21.51 | 52.18 | 76.15 | 78.75 |
| **128×64** | **26.84** | 57.83 | 74.19 | 76.85 |
| 64×128 | 25.81 | **58.23** | 75.31 | 75.64 |
| 256×128 | 11.97 | 58.16 | 76.61 | 62.63 |
| 64×256 | 18.65 | 49.03 | 71.53 | 71.54 |

边界扫描定分派阈值：256³~896³ 小 tile 全面胜出，1024³ 两可（持平），≥2048³ 大 tile 胜。

**分派规则**：`ceil(M/128)×ceil(N/256) < 48（SM 数）→ 128×64，否则 128×256`。

## Step 3 — 实现

- kernel 模板化：`template<typename C> gemm_v12`，Cfg 结构体携带全部派生量（NUM_M/NUM_N/NUM_B_CHUNKS/smem 尺寸）；
- 双实例化：`Cfg<128,256,64,64>`（190 regs / 96KB smem）+ `Cfg<128,64,16,64>`（**88 regs / 48KB smem**）；
- host 分派：一行规则，两份 `cudaFuncSetAttribute`；tensor map 的 A box 高度随 BM（本轮两配置 BM 同为 128）。

## Roofline 重新定位

小形状的填充病被配置族大幅缓解：512³ 的 SM 填充从 17%（8/48）升至 67%（32/48）。剩余缺口：
- **512³ 仍差 cuBLAS 31%**：nvjet 用 64×104 + 128 线程 + 4-stage 的更深定制（我们 128×64 已到 67% 填充，再往上需更小 tile 或 split-K）；
- **1024³ 的 11%**：填充 89%（128 block/2.67 波）但小 tile 的每 SM 效率低（累加器少 → ILP 低），两相抵消——**split-K 是该象限的正解**（未做）。

## 结论：采纳 ✅

v0→v12：512³ 从 11.8 到 26.4，中小形状 +55~126%，大形状零回归。**方法上兑现了 v4 的教训**：本轮先推导结构约束（WN=64 恒定、WM 派生），列出完整可扫维度，六配置一次扫清。

## 关键代码（对照 `gemm_v12.cu` 阅读）

**① 配置结构体（全部派生量集中管理）**：

```cuda
template <int BM_, int BN_, int WM_, int WN_>
struct Cfg {
    static constexpr int BM = BM_, BN = BN_, WM = WM_, WN = WN_;
    static constexpr int NUM_M = WM_ / 16;              // warp tile 内 M 段
    static constexpr int NUM_N = WN_ / 8;               // warp tile 内 N 段（mma n8）
    static constexpr int NUM_B_CHUNKS = BN_ / 64;       // B chunk 数 = warp_n 数
    static constexpr int A_STAGE_BYTES  = BM_ * 128;
    static constexpr int B_STAGE_BYTES  = NUM_B_CHUNKS * (64 * 128);
    static constexpr int TMA_BYTES_PER_STAGE = A_STAGE_BYTES + B_STAGE_BYTES;
    static constexpr int SMEM_BYTES = NUM_STAGES * TMA_BYTES_PER_STAGE + 2 * NUM_STAGES * 8;
};
```

**② 分派规则（一行）**：

```cuda
bool use_small = ((M + 127) / 128) * ((N + 255) / 256) < 48;   // 大 tile 填不满 48 SM
// 小：Cfg<128, 64, 16, 64>（88 regs / 48KB smem）
// 大：Cfg<128, 256, 64, 64>（190 regs / 96KB smem，= v11）
```

**③ warp 排布自适应**：`warp_m = warp / NUM_B_CHUNKS; warp_n = warp % NUM_B_CHUNKS;`——BN 变化时 warp 网格自动重排（128×64 是 8×1 排布：8 个 warp 全在 M 方向）。

**学习要点**：① 配置族的本质是**用编译期模板换运行时灵活性**——两份 kernel 零运行时开销，分派只是一次 host 侧 if；② 扫描前先推导结构约束（WN 被 chunk 宽度锁死在 64），把不可扫维度从空间里剔除，剩下的才是真维度；③ 分派阈值用**填充率**（block 数 vs SM 数）而非矩阵尺寸表达，对非方形自动正确。

## 附加探针（2026-11-09 追加）：后续三个方向的快速判定

### ① split-K：带宽数学判死 ❌

本机实测带宽 255.6 GB/s 下，split-K 的归约流量 ≥3×C 尺寸（写工作区 + 读归约 + 写回）：1024³ 的归约成本 ≥48μs，而填充收益上限 ≤12μs（37μs 计算 × 67%→89% 填充），**收益被归约吃掉 4 倍**。数据中心卡（HBM 数 TB/s）上 split-K 成立、GB10 上不成立——又一个"通用优化定律要过本地 roofline"的实例。（v12.md 初稿曾把 split-K 列为 1024³ 正解，本节更正。）

### ② 128 线程双占空变体（TinyCfg）：证伪 ❌

`Cfg<128,64,32,64,128,2>`（4 warps、WM=32、133 regs、48KB smem → 2 block/SM 成立）实测：256~768³ +0.6~5%（多数在噪声内），**1024³ -17%**（WM=32 低 ILP）。归因：**双占空的主要收益是隐藏 barrier 停顿，而本 kernel 自 v8 起零 `__syncthreads`，无可隐藏**——这是"消除了瓶颈 A 的优化，也消除了针对瓶颈 A 的优化手段的收益"的有趣案例。代码保留于 gemm_v12.cu（`use_tiny=false` 休眠）。

### ③ 512³ 填充的天花板

128×64 下 512³ 填充 67%（32/48）；tile 粒度限制下 64×64 也只有 67%（1.33 波尾损）。要到 cuBLAS 的 83% 需要 64×104 这类非 2 幂 tile（引擎地图已证 nvjet 靠 JIT 做到，预编译框架不可达）——**此项收益归 JIT 专属，文档记录后放弃**。

## 下一步计划（更新后）

1. **FP8 路线**（战略级）：峰值实测 235.79 = BF16 的 2×，指令已验证（`mma.sync.m16n8k32.e4m3`）——剩余方向中唯一的天花板级机会，需新精度路径 + scale 策略 + 新精度门限；
2. **epilogue 与下一 tile 重叠**（大形状 -5.5 实测）：需解决 smem 预算（99KB 中 96KB 被 stage 占用，需 BK=32 缩 stage 或专用 C 暂存区），结构性改动中等；
3. 1024³ 剩余 11% 为短 K 下每 SM 效率（管道固定成本摊薄差），候选：轻量化 prologue/同步，收益预期小。
