# v11 — epilogue 优化（smem 暂存 + TMA store）：+9% ✅ 采纳，4096³ 反超 cuBLAS

- **日期**：2026-11-04
- **文件**：`gemm_v11.cu`（TMA store 版，采纳）；`gemm_v11a.cu`（float2 版，轻量变体，小尺寸/8192³ 略优）
- **前一版本**：v10（84.1 @4096³）

> **接力链**：v10 的写回消融探针指示 = epilogue 是第一大单项瓶颈（2048³ -32%、4096³ -20%：store 碎片化 183 GB/s + 与 mma 完全串行）→ 本版动作 = smem 暂存 + TMA store（4-pass 双缓冲流水；float2 变体同场对比保留为 gemm_v11a）→ 实测 = 88.9 TFLOPS（+9%，**cuBLAS 87.10 的 102%**）。

## Step 1 — 依据（v10 的 epilogue 消融）

写回是 v10 的第一大单项瓶颈（探针 `bench/probe_epi10.cu`）：2048³ -32%、4096³ -20%、8192³ -12%。归因：① store 碎片化（每线程 2×4B 对散写，warp 每条 store 只覆盖 8 行×32B，实测写带宽 ≈183 GB/s < 255.6）；② 1 block/SM 下写回与 mma 完全串行。

## Step 2 — 方案（两个递进变体同场对比）

| 变体 | 机制 | 改动量 |
|---|---|---|
| v11a | **float2 向量写**：相邻 c0/c1 合并成 8B store（gc 偶数 + N 为 8 倍数保证对齐） | 5 行 |
| v11b | **TMA store**：累加器 → smem 暂存（复用 K 循环结束后的 stage 缓冲）→ `cp.async.bulk.tensor` 整 box 异步写回；4 pass × 32 行双缓冲流水；box {64,32}，越界自动裁剪 | epilogue 重写 |

## Step 3 — 实现（v11b 的三个关键点）

1. **暂存与 warp 分区天然对齐**：C tile 的 256 列拆 4 个 [32][64] chunk，`warp_n ↔ chunk`（与 B 加载同构），每 pass 每 warp 只写 1 个 mi 的片段（float2）；
2. **跨代理保序**：generic 写（st.shared）→ `fence.proxy.async.shared::cta`（每线程执行）→ `__syncthreads()` → thread 0 发 4 条 TMA store + commit + `wait_group<1>`（允许 1 组在飞，上一 pass 的缓冲即可覆写）；
3. **修掉一个自己引入的 race（奇数 K 块必触发）**：epilogue 复用 stage 缓冲前必须 `__syncthreads()`——warp 间可错位 ≈1 个迭代，奇数 nkb 时最后一个 K 块恰在 stage 0，落后的 warp 还在读 stage 0 的 A/B，先行的 warp 已把 C 暂存写进去 → 用 C 数据算 mma（垃圾 3.35e38）。v10 的标量写回只碰 global 所以无此问题；**smem 从"读侧"换用途成"写侧"必须全员确认读完**（与 v8 的 arrive race 同族：用途切换点的保序责任）。

## Step 4 — 实测（同会话三版对比）

| 尺寸 | v10 | v11a | **v11** | v11/v10 |
|---|---|---|---|---|
| 512³ | 9.31 | **12.97** | 11.82 | +27% |
| 1024³ | 45.52 | 58.17 | 57.96 | +27% |
| 2048³ | 71.07 | 76.98 | **79.21** | +11.5% |
| **4096³** | 81.49 | 86.50 | **88.9**（×3：89.1/89.1/88.4） | **+9.1%** |
| 8192³ | 92.45 | **95.80** | 94.6（×3：94.7/94.7/94.5） | +2.3% |

- 精度：`max_rel_err=0`，全尺寸 + 4096³×5 + 奇数 K 块回归（1984/4032）+ 非方形 + 1000³ 全 PASS
- 寄存器 190，smem 不变（96KB 复用）

## 结论：采纳 ✅

v0→v11 从 1.26 到 88.9 TFLOPS（70×），**4096³ 反超 cuBLAS**。变体交叉点如实记录：512³/8192³ 上 float2 版（v11a）仍略优（TMA store 的暂存-同步开销在写回占比小时不划算）——配置族（autotune）时可将 epilogue 风格也作为一个切换维度。

### 本轮的方法论收获

1. **smem 用途切换必须全员确认**：读侧（ldsm）转写侧（暂存）若无屏障，warp 错位就是数据竞争——判别实验锁定"奇数 K 块必触发"的规律后根因自明（落后 warp 的最后一块恰在即将被覆写的 stage 上）；
2. **两个变体同场对比**比"一步到位"信息量大：float2 版量化了纯碎片化收益（+2–4% 大尺寸、+9% 小尺寸），证明 TMA store 的额外收益集中在写回占比大的中尺寸；
3. 与 v8 的教训合并成一条通用规则：**mbarrier/TMA 时代，每个"代理/用途切换点"（generic→async、读→写）都要问一遍"谁在保序"**。

## 关键代码（对照 `gemm_v11.cu` 阅读）

**① TMA store 原语（与 load 对称的三件套 + 代理栅栏）**：

```cuda
__device__ __forceinline__ void tma_store_2d(const void* tmap, const void* smem_src, int x, int y) {
    uint32_t s = (uint32_t)__cvta_generic_to_shared(smem_src);
    asm volatile("cp.async.bulk.tensor.2d.global.shared::cta.bulk_group [%0, {%1, %2}], [%3];\n"
                 :: "l"(tmap), "r"(x), "r"(y), "r"(s));
}
__device__ __forceinline__ void tma_store_commit() { asm volatile("cp.async.bulk.commit_group;\n"); }
template<int N> __device__ __forceinline__ void tma_store_wait() { asm volatile("cp.async.bulk.wait_group %0;\n" :: "n"(N)); }
__device__ __forceinline__ void fence_proxy_async() { asm volatile("fence.proxy.async.shared::cta;\n"); }
```

**② epilogue 主体（4-pass 双缓冲流水）**：

```cuda
__syncthreads();                     // ★ 用途切换屏障（race 修复，见 Step 3.3）
for (int p = 0; p < BM / 32; ++p) {
    float* cstg = (float*)(smem_raw + (p % NUM_STAGES) * TMA_BYTES_PER_STAGE)
                  + warp_n * (32 * 64);           // warp_n ↔ chunk（与 B 加载同构）
    /* 本 warp 在 slab 内的 mi（每 pass 恰 1 个）：float2 写暂存
       cstg[rr*64 + cc] = {c0,c1}; cstg[(rr+8)*64 + cc] = {c2,c3}; */
    fence_proxy_async();              // 每线程：generic 写 → async proxy 可见
    __syncthreads();
    if (tid == 0) {
        for (int g = 0; g < 4; ++g)   // 4 个 {64,32} box，越界自动裁剪
            tma_store_2d(&tma_c, chunk_g, block_n + g * 64, block_m + 32 * p);
        tma_store_commit();
        tma_store_wait<1>();          // ≤1 组在飞 → 上一 pass 缓冲可覆写
    }
    __syncthreads();
}
if (tid == 0) tma_store_wait<0>();    // 全部落盘才能退出
```

**③ C 的 tensor map**（host 侧）：`FLOAT32`，gdim {N, M}，box {64,32}，SWIZZLE_NONE——**store 不需要 swizzle**（无 LDSM 读侧），越界由 box 自动裁剪（比手写边界判断更干净）。

**学习要点**：① TMA store 的完成跟踪用 **bulk async group**（per-thread 的 commit/wait_group），与 load 的 **mbarrier 事务字节**是两套独立机制；② `wait_group<1>` 的"N"语义就是双缓冲流水的"允许在飞组数"——与 v3 时代 `cp.async.wait_group<N>` 一脉相承；③ 越界裁剪由 tensor map 边界免费提供，非 8 倍数的 M/N 不需要任何特判。

## 附加探针：warp 特化生产者（第 9 个 warp 专职 TMA）——证伪 ❌

**假设**：v11 同步消融显示同步协议 -17（96→113），根因定位为 thread 0 身兼生产（每 K 块 5 条 TMA + empty 自旋）与消费（全量 mma）双职。照 sm90 的 warp specialization 惯例：288 线程 = 8 消费 warp + 1 生产 warp（lane 0 单线程发 TMA），消费者零生产负担。

**实现要点（探针源码 `bench/probe_warpspec.cu`）**：三分支结构（warp<8 消费 / tid==256 生产 / warp8 lane1-31 落空）——ldsm/mma 是 `.sync.aligned` 集体指令，生产 warp 的残缺 32 线程不得进入消费路径；mbarrier 计数为 1，发射必须单线程。

**实测（同会话交替对比）**：

| 尺寸 | v11 | warp 特化 | Δ |
|---|---|---|---|
| 1024³ | 58.12 | 54.83 | **-5.7%** |
| 2048³ | 77.48 | 73.01 | **-5.8%** |
| 4032³ | 87.71 | 85.08 | -3.0% |
| 4096³ | 79.42 | 75.24 | -5.3% |
| 8064³ | 96.34 | 91.69 | -4.8% |
| 8192³ | 93.45 | 90.75 | -2.9% |

生产者等待改睡眠轮询（`try_wait` 带 suspendTimeHint）后无改善。**全尺寸更差 3~6%，证伪。**

**为什么 sm121 不买账（归因分析）**：
1. **同步消融的 -17 并非纯"thread 0 双职成本"**——消融同时去掉了 TMA 装载流水本身，-17 里含流水固有成本，warp 特化只能拿回双职那份；
2. **专职 warp 的自旋/调度压力是新增成本**：4 调度器的小 SM 上，第 9 个 warp（31 空闲 lane + 1 自旋 lane）挤占 sub-core 发射槽——v11 里 thread 0 的自旋发生在 warp 0 本就要等的窗口内，近乎免费；专职化后变成纯粹的额外压力；
3. **合并控制流的寄存器劣化**：190 regs/16B 栈 → 168 regs/64B 栈（预算从 256 降到 227 上限触发重分配）；
4. sm90 的 warp specialization 有 warp 组调度硬件背书，消费级 4 调度器 SM 没有。

**沉淀**：探针源码保留于 `bench/probe_warpspec.cu`；v12 版号空出。剩余 -17 的攻坚转向（v12 候选重排）：epilogue 重叠（-5.5 实测）与中小形状配置族。
