## Step 1 — Roofline 与瓶颈定位

### v7 配置的消融探针（决定性数据，`bench/probe_v7cfg.cu`）

在 v7 的精确配置下（128×256×32 tile，8 warps，64×64 warp tile，64 mma/warp，128 acc，48 blocks = 1 block/SM）：

| 探针 | TFLOPS | 相对上限代价 |
|---|---|---|
| 纯 mma（64 mma/warp, 128 acc） | **115.7** | 上限 |
| + A-ldsm | 114.3 | -1.3% |
| + B-ldsm | 114.3 | -1.3% |
| + A+B ldsm | 106.0 | -8.4% |
| **+ __syncthreads × 1/K块** | **70.8** | **-33%** |
| 实际 v7（2 sync + cp.async + grid） | 54.6 | — |

### Roofline 判定

```
纯 mma 上限      115.7  ████████████████████████████░ 98%
+ ldsm            106.0  ███████████████████████████░ 90%
+ 1× syncthreads   70.8  ██████████████░░░░░░░░░░░░░░ 60%
实际 v7            54.6  ███████████░░░░░░░░░░░░░░░░░ 46%
```

**v7 是 sync-bound**，不是 memory-bound 也不是 compute-bound：

- B-ldsm 依赖在 v7 配置下几乎消失（-1.3%，对比 2-mma 配置的 -51%——128 acc 的 ILP 完全摊薄了 B 依赖）
- ldsm 合计仅 -8.4%
- **1 次 `__syncthreads` 掉 33%**——这是主瓶颈

### 为什么 `__syncthreads` 在 v7 特别贵（此前探针显示免费）

| | 2-mma 探针（v3 时代） | v7 配置探针 |
|---|---|---|
| 寄存器 | 36 | 198 |
| block/SM | 7 | **1** |
| warp/SM | 56 | **8** |
| barrier 期间可切换 warp | 48（其他 block） | **0**（唯一 block 全部 warp 卡在 barrier） |

v7 的 1 block/SM 意味着 `__syncthreads` 期间**整个 SM 完全空转**。

### 附加验证：TMA 在 v7 配置下无效（v8 第一版）

v8 第一版（TMA 替换 cp.async，保留 1× `__syncthreads`）：55.15 vs v7 54.57（+1%，噪声内）。
**证明 cp.async 的 LSU 争抢在 64 mma/warp 的 ILP 下已被完全隐藏**——加载路径不是瓶颈。

## Step 2 — 方案

用 mbarrier full/empty 双 barrier 替代所有 `__syncthreads`：

```
producer（thread 0）:
    wait(empty_bar[stage])        → 等 buffer 空
    TMA load → arrive_expect_tx(full_bar[stage])  → 数据就绪信号

consumer（所有线程）:
    wait(full_bar[stage])         → 等数据就绪
    ldsm + mma                    → 计算
    arrive(empty_bar[stage])      → 释放 buffer（warp leader）
```

- **零 `__syncthreads`**：producer 只在需复用 3 个 stage 之前的 buffer 时等 empty
- TMA 替换 cp.async：一条指令搬整 tile，thread 0 独占发射（LSU 完全让给 ldsm）
- ldsm/mma 结构与 v7 零改动

### 前置验证

- TMA 编译探针：`cp.async.bulk.tensor.2d` + `mbarrier.arrive.expect_tx` 在 sm_121 可编译
- 之前的 mbarrier 死锁问题已解决：TMA 的 `arrive_expect_tx + complete_tx` 语义比 `cp.async.mbarrier.arrive` 清晰

## 结论：采纳 ✅

+13% 提升（4096³），到达 cuBLAS 的 70.9%。消融探针准确预测了 `__syncthreads` 是主瓶颈（-33%），empty barrier 修复了其中约 1/5。

### 本轮的方法论收获

1. **消融探针必须在目标配置下重跑**：v3 时代的探针显示 `__syncthreads` 免费（56 warp/SM 可互填），v7 配置（1 block/SM）显示 -33%——同一指令的代价取决于 occupancy 上下文
2. **TMA 的前提验证**：先编译探针确认 sm_121 支持，再实测确认加载路径不是瓶颈（v8 第一版无效），最后才是 mbarrier 流水——每步都有数据支撑
3. **mbarrier empty barrier 的 phase 追踪**：producer 侧和 consumer 侧的 phase 必须分开跟踪（第一版 bug：consumer 翻转了 producer 使用的 phase）

# 勘误补录（2026-10-30）：race 的定位、修复与 4-stage 探针

## 一、Race 定位过程

### 症状与触发条件（实测判别）

| 实验 | 结果 | 推论 |
|---|---|---|
| 512³ × 多次 | PASS | race 窗口最窄处（8 blocks、低内存压力） |
| 8 blocks + K=2048（64 次迭代） | PASS | **与 K 长度无关**——排除 K 循环稳态逻辑 bug |
| 16 blocks + K=512 | FAIL | 与并发/布局相关 |
| 8 blocks + 4 个 n-block（256×1024×512） | FAIL | **8 blocks 也能 FAIL**——排除纯并发阈值 |
| 同二进制同尺寸 × 6 | PASS/FAIL 交替 | **间歇性 race 实锤** |
| compute-sanitizer racecheck（512³） | 0 hazards | racecheck 不建模 mbarrier/TMA，对这类 race 失明 |

### 判别实验矩阵（每变体 × 10 次，512×1024×512）

| # | ④ 释放方式 | 结果 | 推论 |
|---|---|---|---|
| 基线 | leader arrive（无 fence） | 6/10 FAIL | — |
| 1 | `__syncthreads()` + leader arrive | 10/10 PASS | race 在「consumer 释放 → producer TMA 覆写」链 |
| 2 | `__syncwarp()` + leader arrive | 6/10 FAIL | warp 级汇合不够 |
| 3 | 256 线程 arrive（count=256） | 5/10 FAIL | 每线程自己的 release arrive 也不够 |
| 5 | fence.acq_rel.cta + 256 arrive | 10/10 PASS | **显式 fence 是关键** |
| 6 | **fence.acq_rel.cta + leader arrive（count=8）** | **10/10 PASS** | **最小修复** ✅ |

### 机制结论

**GB10（SM121，消费级 Blackwell）上 `mbarrier.arrive`（默认 `.release.cta`）不保证先前的 LDSM（ldmatrix）读完成**：arrive 作为 LSU 共享内存原子可越过未完成的 LDSM 数据返回发射。结果：consumer 的 leader arrive 空 barrier → producer 观察到 phase 完成 → TMA 覆写该 stage → 慢 warp 的 ldsm 读到新数据（部分 K-slice 污染，与实测的错误模式吻合：少量元素错、偏差数个单位、间歇出现）。

`__syncwarp()` 无效（执行汇合但不挡发射旁路）；`__syncthreads()` 有效（其 fence 语义 + 到达屏障）；**显式 `fence.acq_rel.cta` 是等价且最便宜的正确修复**。

### 修复与代价

```c
// ④ consumer 释放 stage（每个 warp 的 leader）
asm volatile("fence.acq_rel.cta;\n");   // ← 修复：强制本线程先行 LDSM 读完成
if (lane == 0) mbar_arrive(&empty_bar[s]);
```

- 代价：**-4~5%**（4096³ 61.45→59.11，1024³ 35.08→33.58）——旧数字是 race 版本测的，不作数
- 正确性：512~8192³ 全尺寸 + 4096³×5 + 非方形，全部 PASS、0 误差

## 二、4-stage 探针（修复版基础上）

### Roofline 预判（测前写死）

每 K 块预算：探针计算下限 0.95μs，v8 实际 1.63μs，多出 0.68μs。4-stage 唯一作用机制 = lookahead 2→3 级，掩 TMA 的 L2-miss 延迟尖峰。三种情形：A（到货延迟未掩盖）→ +5~15%；B（自旋开销为主）→ ±2%；C（prologue 变深）→ -0.8%。旁证：cuBLAS 同 3-stage 达 87.1。硬件上限：GB10 smem 99KB/block，4-stage 96KB 刚好塞下，5-stage 不可能。

### 实测（修复版，NUM_STAGES 参数化，smem 72→96KB，occupancy 不变仍 1 block/SM）

| 尺寸 | 3-stage | 4-stage | Δ |
|---|---|---|---|
| 1024³ | 33.58 | 33.77 | +0.6% |
| 2048³ | 49.59 | 50.35 | +1.5% |
| **4096³** | 59.11（3 次均值） | 60.04（3 次均值） | **+1.6%** |
| 8192³ | 63.60 | 63.75 | +0.2% |

精度全 PASS（4096³×3、512³）。**判定：情形 B 证实——+1.6% 在 ±2% 噪声内，不采纳。** smem +24KB 且贴着 99KB 上限无余量，不值得换 1.6%。TMA 到货延迟假设正式关闭。

注：v5 曾证伪 4-stage，但其失败机制（smem↑→occupancy↓）在 v8 配置（已 1 block/SM）不适用——本轮按"消融结论必须在目标配置下重测"规则重新关闭了这个问题，且本轮有明确的 roofline 预判对照。

### 本轮的方法论收获（追加）

4. **精度验证的覆盖面必须与声明一致**：race 在低压力尺寸（512³、8 blocks）窗口闭合——"0 误差"的验证必须覆盖多尺寸 + 多次重复 + 高压工况，否则结论不成立。本轮勘误的直接教训。
5. **GPU 微架构的内存序不能只靠 PTX 规范纸面推理**：`mbarrier.arrive` 默认 release 语义在规范上应排序先行读，但 SM121 实测不行（256 线程各自 release arrive 仍 race）——判别实验矩阵（syncwarp/syncthreads/fence 逐项替换）是定位此类问题的唯一可靠手段。
6. **race 版本的性能数字会"虚高"**：TMA 提前覆写 = 更激进的流水 = +4~5% 假性能。发现正确性 bug 后，此前的性能结论必须全部作废重测。
