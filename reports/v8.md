# v8 — TMA + mbarrier full/empty 流水（消除全部 `__syncthreads`）：+8.5% ✅ 采纳

- **日期**：2026-10-30
- **文件**：`gemm_v8.cu`
- **前一版本**：v7（`618fe53`）

## Step 1 — Roofline 与瓶颈定位

### v7 配置的消融探针（决定性数据，`bench/probe_v7cfg.cu`）

在 v7 的精确配置下（128×256×32 tile，8 warps，64×64 warp tile，64 mma/warp，128 acc，48 blocks = 1 block/SM）：

| 探针 | TFLOPS | 相对上限代价 |
|---|---|---|
| 纯 mma（64 mma/warp, 128 acc） | **116.2** | 上限 |
| + A-ldsm | 114.3 | -1.3% |
| + B-ldsm | 114.3 | -1.3% |
| + A+B ldsm | 106.2 | -8.4% |
| **+ __syncthreads × 1/K块** | **71.0** | **-33%** |
| 实际 v7（2 sync + cp.async + grid） | 54.6 | — |

### Roofline 判定

```
纯 mma 上限      116.2  ████████████████████████████ 98%
+ ldsm           106.2  ███████████████████████████ 90%
+ 1× syncthreads  71.0  ███████████████████░░░░░░░░░ 60%
实际 v7           54.6  ███████████████░░░░░░░░░░░░░ 46%
```

**v7 是 sync-bound**，不是 memory-bound 也不是 compute-bound：

- B-ldsm 依赖在 v7 配置下几乎消失（-1.3%，对比 2-mma 配置的 -51%——128 acc 的 ILP 完全摊薄了 B 依赖）
- ldsm 合计仅 -8.4%
- **1 次 `__syncthreads` 掉 33%**——这是主瓶颈

### 为什么 `__syncthreads` 在 v7 特别贵

| | 2-mma 探针（v3 时代） | v7 配置探针 |
|---|---|---|
| 寄存器 | 36 | 198 |
| block/SM | 7 | **1** |
| warp/SM | 56 | **8** |
| barrier 期间可切换 warp | 48（其他 block） | **0**（唯一 block 全部 warp 卡在 barrier） |

v7 的 1 block/SM 意味着 `__syncthreads` 期间**整个 SM 完全空转**。

### 附加验证：TMA 在 v7 配置下无效（v8 第一版）

v8 第一版（TMA 替换 cp.async，保留 1× `__syncthreads`）：55.15 vs v7 54.57（+1%，噪声内）。
**证明 cp.async 的 LSU 争抢在 64 mma/warp 的 ILP 下已被完全隐藏**——加载路径不是瓶颈。

## Step 2 — 方案

用 mbarrier full/empty 双 barrier 替代所有 `__syncthreads`：

```
producer（thread 0）:
    wait(empty_bar[stage])        → 等 buffer 空
    TMA load → arrive_expect_tx(full_bar[stage])  → 数据就绪信号

consumer（所有线程）:
    wait(full_bar[stage])         → 等数据就绪
    ldsm + mma                    → 计算
    fence.acq_rel.cta             → SM121 必需：保证本线程 LDSM 读完成
    arrive(empty_bar[stage])      → 释放 buffer（warp leader）
```

- **零 `__syncthreads`**：producer 只在需复用 3 个 stage 之前的 buffer 时等 empty
- TMA 替换 cp.async：一条指令搬整 tile，thread 0 独占发射（LSU 完全让给 ldsm）
- **`fence.acq_rel.cta` 是 SM121 的硬性要求**：本芯片上 `mbarrier.arrive` 的隐式 release 不排序先前的 LDSM 读完成，arrive 可先于 ldsm 数据返回完成——没有这条 fence，TMA 会在 consumer 读完成前覆写 stage（间歇性数据竞争）。判别实验（各 ×10 次）：无 fence 6/10 FAIL、`__syncwarp()` 6/10 FAIL、256 线程各自 arrive 5/10 FAIL、显式 fence 10/10 PASS
- ldsm/mma 结构与 v7 零改动

### 前置验证

- TMA 编译探针：`cp.async.bulk.tensor.2d` + `mbarrier.arrive.expect_tx` 在 sm_121 可编译
- mbarrier phase 追踪：producer 侧与 consumer 侧分开跟踪（`phase[]` 与 `prod_empty_phase[]`）

## Roofline 重新定位

```
纯 mma 探针上限      116  ████████████████████████████ 98%
ldsm only 探针      106  ███████████████████████████░ 90%
ldsm + 1 sync 探针   71  ███████████████████░░░░░░░░░ 60%
v8 实际              59  ███████████████░░░░░░░░░░░░░ 50%
cuBLAS               87  ███████████████████████░░░░░ 74%
```

v8（59.2）距 ldsm-only 探针上限（106.2）差 47.0 TFLOPS，来源：
- mbarrier 本身的开销（spin-wait + arrive 原子 + fence）
- grid 效应（10.67 波尾波）
- prologue/epilogue
- TMA 延迟残余（4-stage 探针实测此项 <2%，见下）

## 附加探针：4-stage（lookahead 2→3）

预判：若 TMA 到货延迟是剩余瓶颈 → +5~15%；若自旋开销为主 → ±2%。硬件约束：GB10 smem 99KB/block，4-stage（96KB）是上限，5-stage 不可能。

实测（4096³ 各 3 次均值）：3-stage 59.1 → 4-stage 60.0，**+1.6%，噪声内**。TMA 到货延迟假设关闭，不采纳。

## 结论：采纳 ✅

+8.5% 提升（4096³），到达 cuBLAS 的 68.0%。消融探针准确预测了 `__syncthreads` 是 v7 主瓶颈（-33%），empty barrier 修复了其中约 1/8（35 中的 4.6），其余被 mbarrier/fence 自身开销吃掉。

### 本轮的方法论收获

1. **消融探针必须在目标配置下重跑**：v3 时代的探针显示 `__syncthreads` 免费（56 warp/SM 可互填），v7 配置（1 block/SM）显示 -33%——同一指令的代价取决于 occupancy 上下文
2. **TMA 的前提验证**：先编译探针确认 sm_121 支持，再实测确认加载路径不是瓶颈（v8 第一版无效），最后才是 mbarrier 流水——每步都有数据支撑
3. **SM121 的 mbarrier.arrive 不排序先前 LDSM 读**：empty barrier 释放前必须显式 `fence.acq_rel.cta`；正确性验证必须覆盖多尺寸 + 多次重复（低压力工况会掩盖窗口极窄的竞争）
4. **racecheck/ncu 对此类竞争失明**（mbarrier/TMA 不可见/计数器锁定），判别实验矩阵（逐项替换同步原语）是定位的唯一可靠手段
