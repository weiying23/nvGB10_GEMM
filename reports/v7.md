# v7 — 照抄 cuBLAS 配置（128×256×32，每 warp 64×64）：2.47× 提升 ✅ 采纳

- **日期**：2026-10-26
- **文件**：`gemm_v7.cu`
- **前一版本**：v6（未采纳）；实际基线 v3（`1ebf88c`）

## Step 1 — 依据（v6 教训 + nsys 抓到的 cuBLAS kernel）

cuBLAS 4096³ 的 87 TFLOPS 用的是 `cutlass_80_tensorop_bf16_s16816gemm_128x256_32x3`——
**与我们相同的 mma.sync 指令**，差异只在 warp tile（64×64 vs 16×16）和 ILP 策略。

## Step 2 — 方案（照抄 CUTLASS 2.x sm80 配置）

- BM=128, BN=256, BK=32，8 warps（256 线程，2×4 排布），**每 warp 64×64**
- 每 warp **32 个 mma 输出位置、128 个累加器 float/线程**（低 occupancy 换极高 ILP）
- 3 stage，smem 72KB（dynamic + `cudaFuncSetAttribute`）

## Step 4 — 实测

**第一阶段（无 swizzle）→ 第二阶段（+block swizzle，GROUP_M=8，L2 复用调度）**：

| 尺寸 | v3 | v7 | +swizzle | 提升 | cuBLAS | swizzle后/cuBLAS |
|---|---|---|---|---|---|---|
| 1024³ | 24.34 | 30.74 | 30.76 | 1.26× | 65.31 | 47.1% |
| 2048³ | 25.92 | 43.69 | 44.84 | 1.73× | 87.16 | 51.5% |
| **4096³** | 21.48 | 53.10 | **54.31** | **2.53×** | 87.10 | **62.4%** |
| **8192³** | — | 41.23 | **58.88** | — | 96.15 | **61.2%** |

- swizzle 收益随尺寸增大：8192³ +43%（数据 268MB 远超 L2，复用收益最大）；1024³ 持平（数据全在 L2）
- 精度：`max_rel_err=0`（与 cuBLAS 逐位一致，swizzle 只改调度不改数值）
- 寄存器 198、无 spill、smem 72KB；occupancy：198 寄存器 × 256 线程 → 1 block/SM（约 12.5%），低 occupancy 高 ILP 为有意设计（与 CUTLASS 同策略）
- 512³ 变差（6.22）：tile 太大（grid 仅 8 个 block），48 SM 大量空闲——cuBLAS 靠多 tile 配置解决

## 结论：采纳 ✅

**全项目最大单步提升（4096³ 2.53×，8192³ swizzle 再 +43%）**，验证了两个核心洞察：

1. sm_121 上 mma.sync 的正确策略是「巨大 warp tile（64×64）+ 128 累加器 + 低 occupancy」——用 **ILP 摊薄 ldmatrix 延迟**；
2. 大形状必须配 **block swizzle**——默认 n 优先调度下 B tile 复用距离太远，L2 装不下；swizzle 组内 m 优先让 B tile 连续复用。

适用范围：M/N/K 需对齐（加载路径无边界保护；criterion §5.2 的非对齐与极小形状不在本版支持范围）。

## 距 cuBLAS 还差的 ~38%（62% → 100%）可能的来源

1. block swizzle / L2 复用调度 ✅ 已做进 v7（8192³ +43%）；
2. 3 stage 的同步调度细节（CUTLASS 用 NamedBarrier 细分）；
3. 小形状多 tile 配置（autotune）；
4. 8192³ 的 nvjet 用 TMA 加载（我们的 cp.async 走 LSU，与 ldsm 抢占）。

## 关键代码（对照 `gemm_v7.cu` 阅读）

本版核心 = **照抄 cuBLAS 配置**（128×256×32，每 warp 64×64，128 累加器）+ block swizzle。

**① block swizzle（L2 复用调度）**——全项目性价比最高的一段代码：

```cuda
constexpr uint32_t GROUP_M = 8;
const uint32_t bid = blockIdx.x;
const uint32_t group_size = GROUP_M * num_n_blocks;
const uint32_t group_id = bid / group_size;
const uint32_t in_group = bid % group_size;
const uint32_t m_first = min(group_id * GROUP_M, num_m_blocks);
const uint32_t m_g = min(GROUP_M, num_m_blocks - m_first);
const uint32_t m_block_idx = m_first + in_group % m_g;   // 组内 m 优先
const uint32_t n_block_idx = in_group / m_g;
```

默认调度（blockIdx 直接映射）下 n 优先：同一个 B tile 要隔 num_n_blocks 个 block 才被复用，
L2 24MB 装不下；swizzle 后组内 m 优先，8 个 block 连续用同一份 B tile → L2 命中（8192³ +43%）。

**② 128 累加器 + 64 mma/warp**（低 occupancy 换极高 ILP，摊薄 ldsm→mma 延迟）：

```cuda

#define BN 256
#define BK 32
#define WM 64          // ★ 每 warp 的 warp tile 64×64（v2~v6 是 16×16）
#define WN 64
#define NUM_M 4        // warp tile 内 M 方向 4 段
#define NUM_N 8        // warp tile 内 N 方向 8 段

float c[NUM_M][NUM_N][4];        // ★ 128 个累加器 float/线程（v2 是 8 个）

// 每 K 块：A ldsm 8 条 x4 + B ldsm 8 条 x4.trans + mma 2×4×4×2 = 64 条
```

**③ 3-stage 轮转**（v5 的 4-stage 教训之后回落到 CUTLASS 同款 3）+ `__launch_bounds__(256, 1)`。

**学习要点**：occupancy 从 7 block/SM（36 寄存器）降到 1 block/SM（198 寄存器）反而快 2.5×——
