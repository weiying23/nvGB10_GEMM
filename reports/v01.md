# v1 — 分块 tile + shared memory

- **日期**：2026-10-21
- **文件**：`gemm_v1.cu`
- **前一版本**：v0（`ae13474`）

> **接力链**：v0 的 roofline 指示 = DRAM-bound（数据被重复读 434 倍，AI 4.9 ≪ 463）→ 本版动作 = tile + shared memory 协作复用 → 实测 = 3.24 TFLOPS（2.6×；AI 4.9→12.7 与性能提升完全同步，roofline 定律首次实测验证）。

## Step 1 — 瓶颈（来自 v0 结论）

naive 是 **DRAM-bandwidth-bound**（4096³ 恰好压在 memory 斜线上），AI≈4.9，根因是数据被重复读 434 倍。

## Step 2 — 方案

把 C 切成 32×32 的块，每个 block 协作把 A/B 的 tile 搬进 shared memory，内层从 smem 复用数据累加到寄存器（每线程 2×2 个累加器）。

## Step 4 — 性能与精度验证

| 尺寸 | v0 TFLOPS | v1 TFLOPS | 提升 |
|---|---|---|---|
| 512³ | 1.62 | 2.71 | 1.7× |
| 2048³ | 1.69 | 3.20 | 1.9× |
| 4096³ | 1.26 | **3.24** | **2.6×** |

- 4096³ 相对峰值 2.73%，相对 cuBLAS（87.10）约 3.7%
- 精度：`max_rel_err = 8.1e-05`（2048³）、`9.5e-06`（512³），均 [PASS]（与 v0 一致，优化未引入额外误差）

## Roofline 重新定位

```
v1 AI = 3.24e12 / 255.6e9 ≈ 12.7 FLOP/byte   （v0 是 4.9）
```

**关键验证**：v1 仍精确压在 memory 斜线上（3.24 TFLOPS ≈ 255.6 GB/s × 12.7）。性能提升 2.6× 与 AI 提升 2.6× **完全同步**——印证了 roofline 的核心定律：**memory-bound 时，性能 ∝ 算术强度**。

## 结论

- tile 有效：AI 从 4.9 → 12.7，性能 1.26 → 3.24 TFLOPS，符合理论预期。
- 但仍 **memory-bound**：TM=TN=32 太小，理论 AI = T/2 = 16（实测 12.7），A/B 每个 tile 仍被 N/TN = 128 个 block 重复读，远没到"各读一次"的理想 AI=2048。
- 当前瓶颈不变：**算术强度仍太低（12.7 ≪ 463 转折点）**。

## 下一步（roofline 驱动）

继续提高 AI。方向是**加大输出 tile（TM/TN 32 → 128）**，AI 从 16 → 64。但这会撞上两个新约束，需要一并解决：

1. **寄存器压力**：TM×TN 的累加器总量 = 每线程累加器 × 线程数，tile 加大后每线程累加器暴增，需调整 block 大小或累加器布局；
2. **smem 访问效率**：tile 加大后 smem 读的模式（bank conflict、向量化）开始影响性能，不再是"搬进去就完事"。

预期：若能把 AI 提到 64，性能上限 ≈ 255.6 × 64 ≈ 16 TFLOPS（仍是 memory-bound，但比当前 3.24 高约 5 倍）。

## 关键代码（对照 `gemm_v1.cu` 阅读）

本版核心 = **tile + shared memory 协作复用**。整个 kernel 就三段：

```cuda
__shared__ bf16 As[TM][BK];   // 32×32，A 的 tile 缓存
__shared__ bf16 Bs[BK][TN];   // 32×32，B 的 tile 缓存
float acc[2][2] = {{0}};      // 每线程 2×2 个 C 元素的累加器（寄存器）

for (int k0 = 0; k0 < K; k0 += BK) {
    // ① 协作加载：256 线程把 global 的 32×32 tile 搬进 smem（各自算地址 + 越界补 0）
    for (int i = 0; i < 4; ++i) {                       // 1024 元素 / 256 线程
        int idx = i * 256 + ty * 16 + tx;
        As[idx / BK][idx % BK] = (gr < M && gc < K) ? A[gr * K + gc] : bf16(0.0f);
    }
    ...                                                // Bs 同理
    __syncthreads();                                   // ② 等全 block 搬完

    // ③ 计算：每线程从 smem 读、累加到寄存器（block 内 256 线程共享同一份 tile）
    for (int k = 0; k < BK; ++k) {
        float a0 = __bfloat162float(As[ty][k]);
        float a1 = __bfloat162float(As[ty + 16][k]);
        for (int j = 0; j < 2; ++j) {
            float b = __bfloat162float(Bs[k][tx + j * 16]);
            acc[0][j] += a0 * b;                        // 标量 FMA（CUDA core）
            acc[1][j] += a1 * b;
        }
    }
    __syncthreads();                                   // 防 ① 覆写未读完的 smem
}
// 写回 acc[2][2]
```

**学到的模式**（后续所有版本沿用）：tile 大小 TM×TN 决定数据复用率（AI = TM×TN/(TM+TN)）；
两个 `__syncthreads` 是加载/计算的接缝——它们正是 v3 要流水化、v8 要消灭的对象。
