# fp8_v3：C 以 BF16 写出 —— 2048³ +34%，全形状正收益

> **接力链**：fp8_v2 后非 2 幂缺口 -11.8%（8064 上 182.6 vs 208.1）→ 消融阶梯定位（完整 184.3 / 去写回 212.1 / 去计算 205.9）：**写回 -13.1% 是最大单项**，去写回后反超 cuBLASLt，且纯装载 205.9 = 带宽墙的 85%（计算免费搭乘）→ hpc-ops 图纸确认其零写回机制 = persistent + 独立 C 暂存 + 晚等待，但我们大形状 smem 装不下（96+64>99KB）→ 本版动作 = 确定收益第一步：C 从 FP32 换 BF16 写出（写回字节减半，epilogue 结构不动）→ 实测 = **2048³ +34.3%、4096³ +15.9%、全形状正收益**，精度 8 形状仍逐位一致（对拍同为 bf16 舍入路径）。

---

## Step 1 — 瓶颈定位（v02 附加探针：消融阶梯）

| 消融（8192×8064） | TFLOPS | 揭示 |
|---|---|---|
| 完整 kernel | 184.3 | |
| 去写回（epilogue 全跳） | **212.1** | 写回 -13.1%，最大单项；去写回后反超 cuBLASLt(208.9) |
| 去计算（只跑装载流水） | 205.9 | 纯装载 = 带宽墙 85%；装载与计算完全重叠 |

结论：**差距全在写回**。hpc-ops 的 bf16xfp32 GEMM 确认零写回开销的机制 = persistent tile 循环 + **独立 C 暂存区**（不与 stage 复用）+ 晚等待（`tma_store_wait<0>` 放在下一 tile 的 epilogue 时刻）——写回全程藏在下一 tile 的主循环后面。但其 tile 小（64×64，C 暂存 8KB）装得下独立暂存；我们 128×256 的 C 暂存 64KB（bf16）+ stage 96KB = 160KB 远超 99KB，**结构装不下，persistent 路线（BF16 线三层证伪 + smem 方程）在当前 tile 下不可行**。

可装下的组合（供 v04 评估）：BK=64（stage 48KB）+ MidCfg + bf16 独立暂存 32KB = 80KB ✓——但 BK 减半 = K 块数翻倍（同步开销×2），代价需探针。

## Step 2 — 方案

C 从 FP32 换 BF16 写出——写回字节/tile 从 128KB → 64KB：

- epilogue 暂存类型 `float*` → `__nv_bfloat16*`（[32][64] 每pass 从 8KB → 4KB）；
- 累加器 ×alpha 后 `__floats2bfloat162_rn` 打包成 bf16x2 写入；
- tma_c 换 `CU_TENSOR_MAP_DATA_TYPE_BFLOAT16`（行步长 N×2B，box {64,32} 不变）；
- 精度参照同步换 cuBLASLt 的 bf16 D 路径（阶段 C 已验证该引擎支持）。

**与 BF16 线 v12 证伪的"float2 epilogue 分派"的区别**：那是换风格（写回指令形式，字节不变）且 BF16 下写回占比小（-7%）；本版是换精度（字节真实减半）且 FP8 下写回占比翻倍（-13.1%）——证伪结论不适用，账是新的。

## Step 3 — 关键代码

```cpp
// epilogue 暂存换 bf16（结构零改动，仅类型与打包）
__nv_bfloat16* cstg = reinterpret_cast<__nv_bfloat16*>(
                          smem_raw + (p % NUM_STAGES) * TMA_BYTES_PER_STAGE)
                      + warp_n * (32 * 64);
...
__nv_bfloat162 v0 = __floats2bfloat162_rn(c[mi][ng][0] * alpha, c[mi][ng][1] * alpha);
__nv_bfloat162 v1 = __floats2bfloat162_rn(c[mi][ng][2] * alpha, c[mi][ng][3] * alpha);
*reinterpret_cast<__nv_bfloat162*>(&cstg[rr * 64 + cc]) = v0;
*reinterpret_cast<__nv_bfloat162*>(&cstg[(rr + 8) * 64 + cc]) = v1;
```

## Step 4 — 验证（含 2026-11-21 独立核查轮）

**精度**：8 形状（三分派路径 + 非方形 + 跨边界）vs cuBLASLt FP8→bf16 同精度同 scale，**全部 max_abs_err = 0**——双方同走"f32 累加→bf16 舍入"，逐位一致证明累加结构也相同。

**性能（同会话 v2/v3 交替 ×4 + v3 独立 8 轮 + 消融复核）**：

| 形状 | v2 | v3 | Δ | cuBLASLt（5 轮中位） | v3/lt | vs BF16 v13 |
|---|---|---|---|---|---|---|
| 512³ | 43.4 | 43.6 | +0.6% | 49.6 | 88.0% | 1.46× |
| 1024³ | 98.6 | **102.4** | +3.8% | 87.3 | **117.3%** | 1.76× |
| 2048³ | 121.3 | **163.0** | **+34.3%** | 164.5 | **99.1%** | 2.07× |
| 4096³ | 156.6 | **181.4** | +15.9% | 185.4 | 97.8% | 2.09× |
| 8192³ | 168.0 | **177.8** | +5.8% | 203.2 | 87.5% | 1.87× |
| 8192×8064 | 183.2 | **198.2** | +8.2% | 207.7 | 95.4% | 2.08× |

**增益可信性核查（独立轮）**：2048³ 8 轮 160.6–163.2（极差 1.6%）；512³ cuBLASLt 5 轮 49.2–51.1（中位 49.6，修正此前单发 20.4 离群值）；消融复核 v3 写回占比 7.1%（完整 163.0 / 去写回 175.7）。

**超线性机制（核查④ 反推账）**：v2 写回代价 ≈35μs（25%）→ v3 = 7.5μs（7.1%），字节减半但时间降 4.7 倍。机制：2048³ 时 A+B 各 4MB 全驻 L2（装载不走 DRAM），FP32 C 写流（16MB/140μs = 114GB/s）独占 DRAM 带宽 45% 压住全管线；BF16 写流只占 22%，带宽余量释放 → 主循环同时受益。**中形状（L2 驻留 + 大 C 写流）是此效应的最大受益区**——这解释 2048³ +34% 远超线性预期，也解释 8192³（A+B 已溢出 L2，写流占比相对小）只 +5.8%。
