# fp8_v2：配置族 + 双维分派（tile 尺寸 × 2 幂病理规避）—— 512³ +123%，8192³ +3.2%

> **接力链**：fp8_v1（单 128×256 BigCfg：大形状 1.54–1.80× BF16，但 512³ 仅 18.7 = cuBLASLt 的 37.8%）→ v1 附加探针（GROUP_M 扫描证伪调度序假设；128×128 tile 意外发现病理 -9.5%→-3.4% 且 8192³ 绝对值反超 169.3；nvjet 引擎揭底：**tile 与我们完全相同**的 128×256×128 TMA+swizzle，却对病理免疫）→ 本版动作 = Cfg 模板化（v12 思想移植）+ 三配置 + 双维分派（填充优先 → 2 幂规避 → 默认大配置）→ 实测 = 512³ **18.7→41.8（+123%）**、1024³ +2.6%、8192³ +3.2%、4096³/非 2 幂零回归，精度 9 形状逐位一致。

---

## Step 1 — 瓶颈定位（v1 附加探针，三层递进）

| 探针 | 结果 | 结论 |
|---|---|---|
| C1/C2 病理对照 | 8192³：我们 K=8192 比 K=8064 **慢 11.6%**；cuBLASLt 仅慢 1.1% | 缺口一多半是 2 幂病理，不是带宽 |
| D 引擎揭底（nsys） | `nvjet_sm121_qqtst_mma_128x256x128_2_32x128x128_tmaAB_bz_NNNN` | cuBLASLt **tile 与我们完全相同**——排除 tile 形状与深流水假设 |
| GROUP_M 扫描（2/4/8/16） | GM=8 已是甜点（GM=2 崩到 79） | 调度序打散假设**证伪** |
| 128×128 tile 对照 | 病理 -9.5%→**-3.4%**，8192³ 绝对值 165.4→**169.3** | B 足迹减半摊薄 L2 slice 压力——MidCfg 的立项依据 |

## Step 2 — 方案

配置族三成员 + 双维分派：

```
分派规则（host 侧 if）：
  big_blocks = ceil(M/128)·ceil(N/256)
  which = big_blocks < 48        → SmallCfg(128×64, WM=16)   // 填充优先（v12 经验）
        : (K 是 2 的幂 且 K≥8192) → MidCfg(128×128, WM=32)    // 病理规避
        : 否则                    → BigCfg(128×256, WM=64)    // 非 2 幂大形状最优
```

**分派维度的增量认知**：BF16 线 v12 的分派维度只有“大小”（填充率）；FP8 线发现第二维——**数据布局病理**（2 幂 K）。这是“按输入数据属性分派”的第一次实践。

**MidCfg 的适用边界（本轮实测修正）**：初版分派写的是“2 幂 K 即 MidCfg”，4096³ 实测 **-5.2%**（8 轮分布真实分离：v2 全谱 141–151.5 vs v1 的 152–158.8）——机理：128×128 的 block 数翻倍使 **A 侧总流量 ×1.33**（两个 m-block 各自装载同一 A 行），4096³ 的病理深度较浅（约 -5%），规避收益 < 流量代价；8192³ 病理深（-9.5%）则净正。**修正为 K≥8192 才启用规避**。教训：病理规避配置的收益 = 病理深度 − 流量增量代价，**深度本身随规模增长，阈值必须实测确定**。

## Step 3 — 关键代码

```cpp
// 配置族模板（v12 思想 + FP8 BK=128 常量；WN=64 被 B chunk 宽度锁死）
template <int BM_, int BN_, int WM_, int WN_, int THREADS_ = 256, int BPSM_ = 1>
struct Cfg { /* BM/BN/WM/WN + 派生 warp 网格 + smem 几何，全 constexpr */ };

using BigCfg   = Cfg<128, 256, 64, 64>;   // 非幂大形状
using MidCfg   = Cfg<128, 128, 32, 64>;   // 2 幂 K≥8192（WM 联动：128/4 warp_m）
using SmallCfg = Cfg<128, 64, 16, 64>;    // 填充（WM 联动：128/8 warp_m）

const bool is_pow2_k = (K & (K - 1)) == 0 && K >= 8192;   // 阈值实测（4096³ 净负）
const int which = (big_blocks < 48) ? 2 : (is_pow2_k ? 1 : 0);
```

kernel 体与 v1 逐行同构（`__launch_bounds__` 改用 `C::THREADS, C::BLOCKS_PER_SM`），三配置各自实例化，零运行时分派开销。

## 学习要点

1. **分派维度不止“大小”**：填充率（v12）之外，数据布局病理（2 幂 K）是第二个可分派维度——同 tile 同 TMA 下 nvjet 对病理免疫而我们不能，说明免疫来自更底层的布局细节（bz 的 block 级 swizzle 仍未完全复刻，MidCfg 是“用配置换布局”的迂回）；
2. **病理规避配置有代价函数**：收益 = 病理深度 − A 流量增量（block 数翻倍），两个量都随形状变化，**阈值必须实测**（初版 4096³ -5.2% 的教训）；
3. **探针的意外产出往往比主假设值钱**：GROUP_M 扫描（主目的）证伪了，128×128 对照（对照组）反而成了 v2 的立项依据——**对照组本身也是实验**。
