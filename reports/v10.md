# v10 — TMA + SWIZZLE_128B + BK=64（nvjet 正统路线）：+24% ✅ 采纳

- **日期**：2026-11-04
- **文件**：`gemm_v10.cu`
- **前一版本**：v9（67.9 @4096³）

> **接力链**：v9 的结构矛盾指示 = padded（零冲突）与 mbarrier 零同步互斥（TMA 写不了 padded 布局）→ 本版动作 = TMA `SWIZZLE_128B` 硬件交错合流两者 + BK=64（nvjet 同款，同步减半）→ 实测 = 84.1 TFLOPS（+24%，cuBLAS 96.6%；8192³ 91.7 = 95.4%）。swizzle 公式先探针逐位验证（12288 元素 0 差异），主 kernel 一次通过。

## Step 1 — 依据（v9 的下一步计划 ①）

v9 的 padded 与 v8 的零同步互斥：mbarrier full 依赖 TMA 的 `complete_tx`，而 TMA 写不了 padded 布局（box 内必须连续）。**`SWIZZLE_128B` 模式是合流点**：TMA 写入时硬件自动做 XOR 槽位交错，一次拿到「零 bank conflict + TMA + 零 `__syncthreads`」。这也是 nvjet 全系配置的做法（BK=64、2-stage，引擎地图实测）。

## Step 2 — 方案与前置验证

**swizzle 落位公式**（探针 `bench/probe_tmaswiz.cu` 逐位验证，两种 box 共 12288 元素 0 差异）：

```
box 内元素 (行 r, 内维元素 c)，行距 128B（64 个 bf16）：
物理字节偏移 = r*128 + ((c/8) ^ (r%8))*16 + (c%8)*2
```

**配置**：

| 项 | 值 | 说明 |
|---|---|---|
| tile | 128×256×**64** | BK 翻倍，同步次数减半 |
| A tensor map | box {64,128}，SWIZZLE_128B | 内维 K=64 元素 = 128B；每 stage 1 条 TMA |
| B tensor map | box {64,64}，SWIZZLE_128B | BN=256 拆 4 chunk，**warp_n 天然对应 chunk**；每 stage 4 条 TMA |
| smem | 48KB/stage × **2-stage** = 96KB | lookahead 字节 2×96KB ≈ v9 的 3×27KB |
| mma 循环 | 每 K 块 4 个 k16 slice，**分 2 个 pair** | 片段寄存器 pair 内复用，不膨胀 |
| 同步 | mbarrier full/empty（v8 协议原样，S=2） | 零 `__syncthreads` + fence |

**预判**（v9 报告写死）：67.9 + 零同步 ≈8% + 布局收益 → 78–85。

## Step 3 — 实现

- ldsm 地址按 swizzle 公式手算：A `r*128 + (sub ^ (r&7))*16`，B `warp_n*8KB + k*128 + (nsub ^ (k&7))*16`；
- B 的 4 chunk TMA 写进同一 stage 的连续 8KB 段，expect_tx 合计 49152B；
- 寄存器 190（无溢出），写回与 swizzle 均带边界处理（TMA OOB 填 0 + 写回判断）。

## Roofline 重新定位（含 epilogue 消融，`bench/probe_epi10.cu`）

```
纯 mma                    116.2   98%   ← 理论上限
零冲突 ldsm 流水探针        112.4   95%   ← 计算核极限
v10 去写回（消融探针）      102.1   86%   ← v10 计算核真实水平（4096³）
cuBLAS                     87.1   74%
v10 实际                   84.1   71%   ← 当前位置
```

**epilogue 消融实测（写回 → 归约保活）**——写回是当前第一大单项瓶颈：

| 尺寸 | v10 | 去写回 | 写回成本 |
|---|---|---|---|
| 2048³ | 70.9 | 93.9 | **-23.0（-32%！）** |
| 4096³ | 84.9 | 102.1 | **-17.2（-20%）** |
| 8192³ | 91.0 | 101.8 | **-10.1（-12%）** |

写回为何这么贵（两项叠加）：
1. **store 形态差**：每线程 512B 以 2×4B 对散写，warp 每条 store 只覆盖 8 行 × 32B 的碎片（非 128B 整段）——实测写带宽仅 ≈183 GB/s（<255.6 DRAM 峰值，发射/合并受限而非带宽受限）；
2. **完全串行**：1 block/SM 下写回与 mma 无任何重叠；且写回字节数 ∝ M×N 而 FLOP ∝ M×N×K，K 越小占比越大（2048³ 的 32% vs 8192³ 的 12%）。

剩余 -10（102.1 → 112.4）：prologue + 同步残余 + 尾波（4096³ 尾波 3%）。

**大形状（4096+）已达 cuBLAS 的 95–97%**。剩余差距按尺寸分布：
- 4096³/8192³：3.4%/4.6%——cuBLAS 的 epilogue 必然比我们便宜得多（同写回流量下它只慢 ≈3%）
- **1024³：29.8%（SM 填充病——32 block/48 SM，autotune/split-K 的地盘）**
- 2048³：20.5%（填充 + 写回 32% 双重打击）

## 结论：采纳 ✅

v0→v10 从 1.26 到 84.1 TFLOPS（67×），4096³ 达 cuBLAS 96.6%。本轮的技术要点：
1. **swizzle 公式先探针后编码**——`probe_tmaswiz.cu` 逐位验证后才写 kernel，主 kernel 一次通过零调试；
2. **BK=64 与 2-stage 的配对**是 nvjet 的实测选择，也是 swizzle 约束（box 内维 ≤128B）的自然推论——B 拆 4 box 的发射开销（5 条 TMA/stage）由 thread 0 独占承担，实测无感。

## 关键代码（对照 `gemm_v10.cu` 阅读）

**① TMA + SWIZZLE_128B 的 tensor map**（host 侧）：

```cuda
cuuint32_t box[2] = {64, 128};              // A：内维 K=64 元素(128B)，外维 M=128 行
CK_DRV(cuTensorMapEncodeTiled(&tma_a, CU_TENSOR_MAP_DATA_TYPE_BFLOAT16, 2,
    (void*)dA, gdim, gstr, box, es,
    CU_TENSOR_MAP_INTERLEAVE_NONE, CU_TENSOR_MAP_SWIZZLE_128B,   // ★ 硬件 swizzle
    CU_TENSOR_MAP_L2_PROMOTION_L2_128B, CU_TENSOR_MAP_FLOAT_OOB_FILL_NONE));
// B：box {64,64}，BN=256 由 4 次 TMA 拼（warp_n 天然对应 chunk）
```

**② swizzled ldsm 地址**（kernel 侧，公式与 TMA 写入侧严格互逆）：

```cuda
// A：逻辑 (行 r, K 元素 c)，sub = c/8（16B 槽号）
uint32_t addr = __cvta_generic_to_shared(
    a_base + r * 128 + (sub ^ (r & 7)) * 16);          // ★ XOR 交错
asm volatile("ldmatrix.sync.aligned.x4.m8n8.shared.b16 ...");

// B：chunk = warp_n（0..3），逻辑 (K 行 k, N 元素 n)，nsub = n/8
uint32_t addr = __cvta_generic_to_shared(
    b_base + warp_n * 8192 + k * 128 + (nsub ^ (k & 7)) * 16);
asm volatile("ldmatrix.sync.aligned.x4.trans.m8n8.shared.b16 ...");
```

**③ producer：每 stage 5 条 TMA 合写一个 mbarrier**：

```cuda
auto issue_stage = [&](int s, int kb) {
    mbar_arrive_expect_tx(&full_bar[s], TMA_BYTES_PER_STAGE);   // 49152B
    tma_load_2d(&tma_a, a_dst, &full_bar[s], kb * BK, block_m);
    for (int g = 0; g < 4; ++g)                                  // B 拆 4 chunk
        tma_load_2d(&tma_b, b_dst + g * 8192, &full_bar[s], block_n + g * 64, kb * BK);
};
```

**④ mma 循环：BK=64 分 2 个 pair，片段寄存器不膨胀**：

```cuda
#pragma unroll
for (int p = 0; p < 2; ++p) {           // 每 pair：2 个 k16 slice
    /* 16 条 ldsm（8 A + 8 B）→ a[2][4][4] + b[2][4][4]（64 个片段寄存器，pair 内复用）*/
    /* 64 条 mma（2 ks × 4 mi × 8 ni）*/
}
// 每 K 块共 128 mma；寄存器 190（v9 为 200），无溢出
```

**学习要点**：① swizzle 的本质是「加载侧（TMA 硬件）与读取侧（ldsm 地址）共用同一个 XOR 函数」——两侧一致则布局任意复杂都不会错，探针先行验证就是把这个一致性从"祈祷"变成"证明"；② B 拆 4 box 后 `warp_n` 直接当 chunk 索引，warp 排布与 smem 分区天然对齐。

## 非 2 幂形状实测（2026-11-04 追加）

对齐检查从 16 的倍数放宽到 **8 的倍数**（TMA 真实约束只是 global stride 16B 对齐；`K/N=8k` 即满足），支持面扩大且精度全 PASS：

| 形状 | v10 | cuBLAS | 比值 | 说明 |
|---|---|---|---|---|
| 1000³ | 42.12 | 60.84 | 69.2% | 8 倍数（16 倍数也不是）；K=1000 非 BK=64 整数倍，TMA 补零，误差 8.1e-06 ≪ 1e-3 |
| 2000³ | 64.89 | 90.85 | 71.4% | cuBLAS 反而超过它自己的 4096³（87.1）——nvjet 现场合成完美契合的 tile 消掉尾波 |
| 4032³ | 85.86 | 88.15 | **97.4%** | 大尺寸非 2 幂我们反而咬得更紧 |
| 2048×2016×4032 | 77.29 | 94.34 | 81.9% | 非方形 |

结论：非 2 幂的正确性与大尺寸性能没有额外代价（4096³ 96.6% vs 4032³ 97.4%）；**中尺寸的差距与 2 幂尺寸同源**（SM 填充病），但 cuBLAS 在中尺寸非 2 幂上靠 JIT 定制 tile 反而更强（2000³ 拿到 90.85 > 87.1）——填充病是 v11 配置族的又一块论据。非 8 倍数尺寸（如 999）仍不支持，需要 padding 兜底 kernel（未来项）。

## 下一步计划（按优先级，epilogue 消融后更新）

1. **v11 主攻：epilogue 优化**——写回是当前第一大单项瓶颈（4096³ -20%、2048³ -32%），且全尺寸通吃。方案按代价递增：
   a. **store 向量化**：重排写回映射使每线程 128-bit 对齐写（st.global.v4），预期把写带宽从 183 拉向 250 GB/s；
   b. **TMA store**（`cp.async.bulk.tensor` global←shared）：累加器 → smem → 整 tile 一次异步写回（128B 段、发射后即返回）；
   c. **与下一 tile 重叠**（tile 间流水）。
   预期 84.1 → 95+（超过 cuBLAS 87.1）。
2. **中小形状配置族**（1024³ 的 30% 填充病）：小 tile 变体或 split-K + 归约。
3. **FP8 路线**（探索性）：峰值实测 235.79 TFLOPS = BF16 的 2×，指令已验证可用——天花板翻倍的机会，精度策略另议。
